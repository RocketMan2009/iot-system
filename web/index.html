คลิกขาสีเขียวบนรูปบอร์ดเพื่อใช้เป็นรีเลย์ — ลำดับที่คลิกคือ CH1, CH2, … · คลิกซ้ำเพื่อเอาออก · ขาสีอื่นต่อรีเลย์ไม่ได้ (ชี้เมาส์ที่ขาเพื่อดูเหตุผล)

ช่องรีเลย์ที่เลือก

    เชื่อมต่อบอร์ดผ่าน USB เพื่อบันทึก — วางแผนต่อสายได้เลยโดยไม่ต้องต่อบอร์ด

    ผังการต่อวงจร — เปลี่ยนตามขาที่เลือกด้านบนทันที (ชี้เมาส์ที่สายเพื่อดูรายละเอียด)

    ผังต่อสายรีเลย์ & ทดสอบ ON / OFF

    ทดสอบผ่าน USB ได้โดยไม่ต้องมี Wi-Fi

    ต่อขา GPIO ของ ESP32 เข้าขา IN ของโมดูลรีเลย์ช่องเดียวกัน (CH1 → IN1 …) · GND ของ ESP32 ต่อร่วมกับ GND ของโมดูล · ไฟเลี้ยงโมดูล 5V ต่อจากขา 5V ของบอร์ดหรือแหล่งจ่ายแยก

    ช่องESP32 pinตำแหน่งบน DevKitCต่อเข้าMQTT topic (สั่งงาน)สถานะทดสอบ
    เชื่อมต่อบอร์ดผ่าน USB เพื่อดูผังขาและทดสอบรีเลย์

    วิธีใช้
    
          
      
            
    1. เสียบ ESP32 ผ่าน USB (Windows: ติดตั้งไดรเวอร์ CP210x หรือ CH340 ครั้งแรก)
      2. 
            
    2. กด “แฟลชเลย” เพื่อใช้เฟิร์มแวร์ล่าสุดที่ build ไว้บนเว็บนี้ — หรือเลือกไฟล์ .bin ที่ build เอง
      3. 
            
    3. ปิดโปรแกรม/แท็บอื่นที่ใช้พอร์ตอยู่ (Serial Monitor, แท็บ “ตั้งค่าบอร์ด”) แล้วเลือกพอร์ต COM ของบอร์ด
      4. 
            
    4. DevKitC เข้าบูตโหลดเดอร์เองผ่าน DTR/RTS — ถ้าไม่สำเร็จ ให้กดปุ่ม BOOT ค้างไว้ระหว่างเริ่มเชื่อมต่อ
      5. 
            
    5. เสร็จแล้วไปแท็บ “ตั้งค่าบอร์ด” เพื่อใส่ Wi-Fi และ MQTT
      6.

    วงจรการต่ออุปกรณ์
    
          
    
            
            
          
    
        
    
        
    
          ผังนี้วาดตามขารีเลย์ที่เลือกในแท็บ “ตั้งค่าบอร์ด (USB)” — เปลี่ยนขาที่นั่นแล้วรูปนี้เปลี่ยนตามทันที ·
          ชี้เมาส์ที่สายเพื่อดูว่าต่อจากขาไหนไปขาไหน
        
    
        
    
        
    
          
    
          
      
            
    • ไฟเลี้ยงโมดูล: VCC → 5V ของบอร์ด (หรือแหล่งจ่าย 5V แยก) · GND ต้องต่อร่วมกับ GND ของ ESP32 เสมอ
      • 
            
    • สายสัญญาณ: GPIO แต่ละขา → IN ของช่องเดียวกัน (CH1 → IN1 …) โมดูลส่วนใหญ่เป็น Active-LOW
      • 
            
    • ฝั่งไฟบ้าน: สาย L เข้า COM · ขา NO ไปที่เครื่องใช้ไฟฟ้า · สาย N ต่อตรงเข้าเครื่องใช้ไฟฟ้า (ไม่ผ่านรีเลย์)
      • 
            
    • NO = ปกติเปิดวงจร (สั่ง ON แล้วไฟไหล) · NC = ปกติปิดวงจร (ใช้กลับด้าน)
      • 
            
    • ⚠ งานไฟ 220V ต้องตัดไฟก่อนต่อสาย ใช้รีเลย์ที่รับกระแสได้พอ (เช่น 10A) และติดตั้งในกล่องปิดมิดชิด
      • 
          
    
        
    
      
    

      
    
        
    
          
    สถาปัตยกรรม MQTT
    
          เปิดภาพเต็ม
        
    
        
    
          
        
    
      
    

      
    
        
    
          
    ลำดับการสั่งงาน 1 ครั้ง
    
          
      
            
    1. ① PUB เว็บหรือแอปภายนอกส่ง ON ไปที่ <base>/<id>/relay/N/set
      2. 
            
    2. ② ส่งต่อ broker ส่งต่อให้ ESP32 ที่ subscribe relay/+/set ไว้
      3. 
            
    3. ③ GPIO ESP32 สั่งขา GPIO ของช่องนั้น → รีเลย์ทำงาน และจำสถานะลง NVS
      4. 
            
    4. ④ PUB state ESP32 ยืนยันสถานะจริงไปที่ relay/N/state (retained)
      5. 
            
    5. ⑤ อัปเดต ทุก client ที่ subscribe อยู่เห็นสถานะใหม่พร้อมกัน
      6. 
          
    
        
    
        
    
          
    ทำไมออกแบบแบบนี้
    
          
      
            
    • แยก set / state — สถานะบนจอมาจากบอร์ดจริงเสมอ และคำสั่งเก่าไม่ถูกสั่งซ้ำตอน reconnect
      • 
            
    • Retained + LWT — เปิดเว็บเมื่อไหร่ก็เห็นสถานะล่าสุดทันที และรู้ว่าบอร์ดไหนออฟไลน์
      • 
            
    • ไม่มี server ของตัวเอง — เว็บเป็นไฟล์ static บน GitHub Pages, broker คือแหล่งข้อมูลเดียว
      • 
            
    • TLS ทุกเส้น — บอร์ดใช้ 8883, เว็บใช้ WSS 8884, ต้องมี username/password
